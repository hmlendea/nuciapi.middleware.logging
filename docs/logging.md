# Logging

## Logging Framework

- **Library**: NuciLog (v1.2.1) with NuciLog.Core (v3.1.0) abstraction
- **Abstraction**: `NuciLog.Core.ILogger` injected via DI
- **Implementation**: NuciLog (typically Serilog sink)
- **Configuration Source**: Consumer application (not this library)

## Log Levels

| Level | Used? | Semantics |
|-------|-------|-----------|
| Debug | No | — |
| Information | Yes | Request Started, Request Success |
| Warning | No | — |
| Error | Yes | Request Failure (non-2xx), Request Failure (exception) |
| Fatal | No | — |

## Structured Fields

Every log event includes these standard properties via `MyLogInfoKey`:

| Field | Type | Always Present | Description |
|-------|------|----------------|-------------|
| `Method` | string | Yes | HTTP method |
| `Path` | string | Yes | Request path |
| `QueryString` | string | Yes | Raw query string (may be empty) |
| `IpAddress` | string | Yes | Client IP address |
| `Hostname` | string | Yes | Hostname(s) for IP |
| `ClientId` | string? | No | From `X-Client-Id` header |
| `RequestId` | string? | No | From `X-Request-Id` header |
| `Timestamp` | string? | No | From `X-Timestamp` header |
| `HmacToken` | string? | No | From `X-Hmac-Token` header |
| `StatusCode` | int | Terminal events only | HTTP response status |
| `ElapsedMilliseconds` | long | Terminal events only | Request duration |

## Correlation

### Request Correlation

- `RequestId` header (`X-Request-Id`) — client-provided correlation ID
- If absent, no correlation ID generated by this middleware
- Passed through to log events for downstream correlation

### Trace Context

- No W3C TraceContext support built-in
- Consumers should add trace middleware upstream if needed

## Sinks/Destinations

Determined by consumer's NuciLog configuration. Typical sinks:
- Console (development)
- File (rolling, JSON)
- Seq, Elasticsearch, Datadog, etc. (via Serilog sinks)

This library does not configure sinks.

## Redaction/Masking

| Field | Redacted? | Reason |
|-------|-----------|--------|
| `HmacToken` | No | Logged as-is (consumer responsibility) |
| `ClientId` | No | Identifier, not secret |
| `RequestId` | No | Correlation ID |
| `Timestamp` | No | Request timestamp |
| All others | No | Non-sensitive |

**Note**: This middleware does not perform redaction. Consumers should configure NuciLog/Serilog destructuring policies to mask sensitive fields.

## Retention

Not managed by this library. Consumer responsibility via sink configuration.

## Sampling

Not implemented. All requests logged at Information/Error level.

## Performance Considerations

- **Async logging**: NuciLog uses async sinks (Serilog async)
- **Allocation**: `LogInfo[]` allocated per request (11-13 elements)
- **Stopwatch**: Minimal overhead
- **Hostname lookup**: `NetworkUtils.GetHostnames` may perform DNS reverse lookup — potential latency

### Optimisation Opportunities

1. Cache hostname lookups
2. Use `ValueTask` for hot paths (not currently)
3. Pool `LogInfo` arrays (not currently)

## Error Logging

### Exception Logging

When downstream throws:
```csharp
logger.Error(
    MyOperation.HttpRequest,
    OperationStatus.Failure,
    ex,                    // Exception with stack trace
    logInfos);             // Request metadata
```

Includes:
- Full exception (type, message, stack trace)
- Inner exceptions
- Request metadata from `Started` event

### Non-2xx Logging

```csharp
logger.Error(
    MyOperation.HttpRequest,
    OperationStatus.Failure,
    logInfos);             // Request + response metadata
```

No exception object — status code indicates failure.

## Audit Logging

No separate audit log. All events go through same `ILogger` with `HttpRequest` operation.

Security-relevant events captured:
- All requests (Started)
- Failed requests (Failure with status code)
- Exceptions (Failure with exception)

## Configuration

Logging configured by consumer via NuciLog:

```csharp
builder.Services.AddNuciLog(options =>
{
    options.MinimumLevel = LogLevel.Information;
    options.Enrich.FromLogContext();
    options.WriteTo.Async(a => a.Console());
    options.WriteTo.Async(a => a.File("logs/requests-.log"));
});
```

### Runtime Level Changes

Supported via NuciLog/Serilog `LoggingLevelSwitch` — consumer responsibility.
